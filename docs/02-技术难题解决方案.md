## 难题 1：`file://` 下 IndexedDB / WebAudio 失效，存档丢失 ★★★★★

**现象**：若把 HTML 放进 assets 用 `file:///android_asset/` 加载，游戏能开，但 ROM 导入失败、存档报 `SecurityError`、音频无声。

**根因**：`file://` 是不透明 origin，浏览器/WebView 会限制 IndexedDB、crypto.subtle、WebAudio 的某些能力。原项目的 `serve.py` 也明确要求用 http 打开，原因相同。

**解决方案**：用 AndroidX `WebViewAssetLoader` 把 assets 映射到 `https://appassets.androidplatform.net/`，让页面运行在真实 https origin 上。

```kotlin
val assetLoader = WebViewAssetLoader.Builder()
    .setDomain("appassets.androidplatform.net")
    .addPathHandler("/assets/", WebViewAssetLoader.AssetsPathHandler(this))
    .build()
// shouldInterceptRequest 中：
override fun shouldInterceptRequest(view, request) =
    assetLoader.shouldInterceptRequest(request.url)
webView.loadUrl("https://appassets.androidplatform.net/assets/GBA-60Hz.html")
```

**代码位置**：`MainActivity.kt` → `assetLoader` / `webViewClient.shouldInterceptRequest` / `APP_URL`。

## 难题 2：ROM 导入 —— WebView 的 `<input type=file>` 不会自己弹出系统文件选择器 ★★★★★

**现象**：页面里"载入 ROM"按钮点了没反应，`<input type="file">` 被点击但 Android 不弹文件管理器。

**根因**：WebView 不实现文件选择 UI，必须通过 `WebChromeClient.onShowFileChooser` 把选择请求转发给宿主 Activity。

**解决方案**：
1. 重写 `onShowFileChooser`，保存 `ValueCallback`。
2. 用 Android SAF `ActivityResultContracts.OpenMultipleDocuments()` 选文件；目录用 `OpenDocumentTree()`。
3. 选中后把 `content://` Uri 数组回传给 callback。
4. `takePersistableUriPermission` 保证重启后 Uri 仍可读。

**代码位置**：`MainActivity.kt` → `openDocumentsLauncher` / `openTreeLauncher` / `onShowFileChooser` / `deliverFileResult`。

**注意**：
- 大 ROM（几十 MB）经 SAF 读入 WebView 内存后再写 IndexedDB，可能触发 OOM。页面已有 512MB 单文件上限判断；建议真机测试最大可导入尺寸，必要时在原生侧用流式分块读取。
- `webkitdirectory`（整文件夹导入）在 WebView 支持不完整；当前用 `OpenDocumentTree` 兜底，但返回的是树 Uri 而非文件列表，可能需要额外遍历逻辑（见文档三"已知限制"）。

## 难题 3：WebAudio 自动播放策略导致无声 ★★★★

**现象**：进游戏后没声音，需再点一下屏幕才恢复。

**根因**：Chrome/WebView 的 autoplay policy 要求用户手势后才能启动 AudioContext。模拟器页面加载与进游戏是 JS 自动触发的，可能不满足"手势"条件。

**解决方案**：
1. `settings.mediaPlaybackRequiresUserGesture = false`（对 `<video>/<audio>` 生效）。
2. 对 WebAudio：页面内的 `AudioContext` 通常仍需一次 resume。页面原逻辑在首次触摸/按键时会 resume；原生侧只需保证不额外拦截触摸。
3. 切后台 `onPause` 时页面自身 `visibilitychange` 会 suspend 音频，回前台 `startLoop()` 会 resume——与网页版一致。

**代码位置**：`MainActivity.configureWebView`（mediaPlaybackRequiresUserGesture）；页面侧音频逻辑无需改动。

## 难题 4：全屏与横屏切换 ★★★★

**现象**：点页面全屏按钮后无效，或横屏后状态栏/导航栏遮挡画面。

**根因**：WebView 内的 Fullscreen API 需要宿主提供承载视图；单纯 `requestFullscreen()` 在 WebView 里不会真正全屏。

**解决方案**：重写 `WebChromeClient.onShowCustomView/onHideCustomView`，把全屏 View 加到根 FrameLayout，隐藏 WebView，并加 `FLAG_FULLSCREEN`。

```kotlin
override fun onShowCustomView(view: View?, callback: CustomViewCallback?) {
    customView = view; customViewCallback = callback
    root.addView(view, MATCH_PARENT, MATCH_PARENT)
    webView.visibility = View.GONE
    window.addFlags(WindowManager.LayoutParams.FLAG_FULLSCREEN)
}
```

**代码位置**：`MainActivity.kt` → `onShowCustomView` / `exitCustomView`。

**补充**：页面自身有 `screen.orientation.lock('landscape')`（`app.html` 第 4120 行）。在 WebView 中 Screen Orientation API 支持有限，可能不生效；此时依赖 Android 侧的物理旋转 + `android:configChanges` 自己处理配置变化（Manifest 已配置 `configChanges`），页面 `resize()` 会自适应。

## 难题 5：实体返回键行为 ★★★★

**现象**：按返回键直接退出 App，即使设置页/菜单正开着，体验很差。

**根因**：WebView 默认消费返回键或 Activity 默认 finish，未区分当前 UI 状态。

**解决方案**：用 `OnBackPressedDispatcher`，先询问页面是否有可关闭的 UI（modal/settings），页面返回 `true` 表示已消费；否则才退出。

```kotlin
onBackPressedDispatcher.addCallback(this, object : OnBackPressedCallback(true) {
    override fun handleOnBackPressed() {
        when {
            customView != null -> exitCustomView()
            else -> webView.evaluateJavascript(Js.GO_BACK) { r ->
                if (r != "true") finish()
            }
        }
    }
})
```

`Js.GO_BACK` 检查 `#modal.on` / `#settingsPage.on` 并调用页面 `closeSheet()` / `closeSettings()`。

**代码位置**：`MainActivity.kt` → `onBackPressedDispatcher` / `Js.GO_BACK`。

## 难题 6：`navigator.share` / `navigator.vibrate` 在 WebView 不可用或行为不一 ★★★

**现象**：截图分享点了没反应；按键震动无感。

**根因**：多数第三方/定制 WebView 未实现 Web Share API；`navigator.vibrate` 在某些 ROM 被裁剪。

**解决方案**：
- **分享**：注入脚本在 `!navigator.share` 时提供降级实现，调用 `GbaNative.shareText`；截图分享还可走原生 ACTION_SEND 图片（可扩展 `shareImage`）。
- **震动**：`GbaBridge.vibrate` 直接用 Android `Vibrator` / `VibratorManager`，兼容 Android 8+ 的 `VibrationEffect` 与旧 API，解析页面传来的 `[0,8,14,22]` 风格 pattern。

**代码位置**：`MainActivity.Js.INJECT`（分享降级）/ `GbaBridge.kt` → `vibrate` / `shareText`。

## 难题 7：截图下载 —— WebView 下载管理器不可靠 ★★★

**现象**：页面 `screenshot()` 用 `<a download href=blob:...>` 触发下载，WebView 里可能无反应或存到不可见位置。

**根因**：WebView 对 `blob:` 下载、`download` 属性、`DownloadListener` 的支持各版本不一致。

**解决方案**：注入脚本劫持 `HTMLAnchorElement.prototype.click`，遇到 `blob:` + `download` 时用 `fetch(blob)` → `FileReader.readAsDataURL` → `GbaNative.saveData(dataUrl, filename)` 走原生保存并触发媒体扫描。

**代码位置**：`MainActivity.Js.INJECT` / `GbaBridge.saveData` / `setDownloadListener` 兜底。

**补充**：`GbaBridge.saveData` 用 `MediaStore`（Android 10+ 用 `RELATIVE_PATH = DCIM/GBA60Hz`）保证图库可见；Android 9- 直接写公共 Downloads 目录。

## 难题 8：后台生命周期 —— 切后台要暂停 + 存档，回前台要恢复 ★★★★

**现象**：切到后台游戏继续跑（耗电/发热/丢进度），或回前台音频错乱。

**根因**：WebView 切后台时 JS 计时器可能被节流但仍运行；需要显式暂停并存档。

**解决方案**：
1. 页面自身已有 `visibilitychange` → `autoSave + running=false + audio.suspend`（`app.html` 第 4708 行附近）。
2. 原生 `onPause` 额外注入 `autoSave(true)` 兜底。
3. WebView 的 `onResume/onPause` 会触发页面 visibilitychange，回前台页面 `startLoop()` 自动恢复。

**代码位置**：`MainActivity.onPause` / `Js.PAUSE`；页面侧 visibilitychange 逻辑（无需改动）。

---

## 难题 9：WebGL / GPU 在部分设备不可用 ★★★

**现象**：低端机或开启省电模式时 WebGL 上下文创建失败，画质增强失效。

**根因**：设备 GPU 驱动差异、省电模式限制 WebGL。

**解决方案**：
- 页面本身已有完善降级：`initGL()` 失败自动切回 2D 渲染，功能不丢失（`app.html` 已有 `GL.ok` / `webglcontextlost` 处理）。
- 原生侧开启硬件加速 `webView.setLayerType(LAYER_TYPE_HARDWARE, null)`。
- Manifest 不关闭硬件加速（默认开启）。

**代码位置**：`MainActivity.configureWebView`；页面侧渲染降级逻辑（无需改动）。

## 难题 10：大 ROM 导入的内存与性能 ★★★

**现象**：导入 100MB+ 的 ROM 时卡顿或被系统杀进程。

**根因**：文件经 SAF → WebView → JS `Uint8Array` → IndexedDB 全程在内存，峰值内存约为文件大小的 2~3 倍。

**解决方案**（分层）：
1. 页面已有 512MB 上限与流式 ZIP 解压（`DecompressionStream`）。
2. 建议真机实测可用上限（多数设备 64~128MB ROM 无障碍）。
3. 若需支持超大 ROM：在原生存下 Uri，页面按需 `fetch(content://)` 分块读取——需扩展桥接，属进阶优化。

**代码位置**：页面导入逻辑（`app.html` 导入区块）；`MainActivity.onShowFileChooser`。

---

## 难题 11：外链误跳转 / 页面被劫持 ★★

**现象**：页面里若有链接，点击后在 WebView 内打开导致布局错乱。

**根因**：WebView 默认在自身加载所有 URL。

**解决方案**：`shouldOverrideUrlLoading` 中，非本地 origin 的 http(s) 链接交给系统浏览器；`blob:`/`data:` 放行。

**代码位置**：`MainActivity.webViewClient.shouldOverrideUrlLoading`。

---

## 难题 12：用其他应用打开 .gba ★★

**现象**：想从文件管理器直接点 .gba 用本 App 打开。

**根因**：需注册 intent-filter 并读取 content Uri。

**解决方案**：Manifest 注册 `ACTION_VIEW` + `.gba` 的 `content` scheme；`handleIncomingIntent` 读取字节转 base64，注入 JS 调用页面 `loadRom()`。

**代码位置**：`AndroidManifest.xml` intent-filter / `MainActivity.handleIncomingIntent` / `Js.INJECT` 的 `GbaNativeOpenExternal`。

**注意**：`pathPattern` 对 content Uri 的匹配可能不生效（Android 对 content scheme 的 pathPattern 支持有限）；更稳妥是根据 MIME 或让用户从分享菜单选择。此为已知边界。

## 难题 13：ProGuard 混淆导致 JS 桥接失效 ★★

**现象**：release 包里 `GbaNative.xxx()` 调用报 `TypeError`，debug 包正常。

**根因**：混淆重命名了带 `@JavascriptInterface` 的方法，JS 通过方法名查找失败。

**解决方案**：`proguard-rules.pro` 保留桥接类方法：

```proguard
-keepclassmembers class com.gba60hz.app.GbaBridge {
    @android.webkit.JavascriptInterface <methods>;
}
```

**代码位置**：`app/proguard-rules.pro`。当前 `isMinifyEnabled = false`，启用混淆时必须保留此规则。

## 难题 14：主题与沉浸式状态栏 ★

**现象**：状态栏颜色与黑底游戏界面不搭，出现割裂感。

**解决方案**：主题设黑色状态栏/导航栏，NoActionBar；`windowNoTitle`。页面 UI 本身是深色，配合黑底沉浸式。

**代码位置**：`res/values/themes.xml` / `values-night/themes.xml`。

---

## 难题 15：Kotlin `const val` 不能用字符串模板（开发期踩坑）★

**现象**：编译报错 "Const 'val' initializer should be a constant value"。

**根因**：`Js.INJECT` 是 `const val`，其中用 `${BRIDGE_NAME}` 模板插值，Kotlin 不允许。

**解决方案**：把桥接名在 JS 字符串中写死为 `GbaNative`（与 `MainActivity.BRIDGE_NAME` 保持一致），`const val` 用纯字面量。

**代码位置**：`MainActivity.Js.INJECT`。
