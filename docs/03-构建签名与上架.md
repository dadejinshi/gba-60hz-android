# 文档三：构建、签名与上架指南

---

## 1. 前置条件

- **Android Studio**（推荐 Ladybug 2024.2 或更新），首次打开会自动下载 Gradle 8.9 与 Android SDK 35。
- 或命令行：JDK 17 + Android SDK（platform 35, build-tools 35.x）+ Gradle 8.9。
- 本项目为 Gradle Kotlin DSL（`.kts`），用 Android Studio 打开根目录 `GBA-Android/` 即可，无需额外配置。

> 生成环境说明：本沙盒有 JDK 20 / Gradle 9.3，但**未安装 Android SDK**，因此无法在此处产出 APK。
> 代码已按 Android Studio 标准结构编写，需在装有 SDK 的 Android Studio 中构建验证（见 §5 检查清单）。

---

## 2. 首次构建（Debug）

```bash
cd GBA-Android
# 用 Android Studio：打开项目 → 等待 Gradle 同步 → Run 'app'（选真机或模拟器）
# 命令行：
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

安装：
```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

---

## 3. 同步最新 Web 成品

每次你在 `GBA-60Hz/web/` 改了前端并重新 `python3 build.py` 后，把新的单文件同步进 Android 项目：

```bash
cd GBA-Android
bash tools/sync_assets.sh
# 或指定任意源：bash tools/sync_assets.sh /path/to/GBA-60Hz.html
```

脚本会复制到 `app/src/main/assets/GBA-60Hz.html` 并检查占位符是否残留。

## 4. 生成签名密钥与 Release 包

### 4.1 生成 keystore（一次）

```bash
keytool -genkeypair -v \
  -keystore gba60hz-release.jks \
  -alias gba60hz \
  -keyalg RSA -keysize 2048 -validity 10000
# 记住口令与 alias；务必离线备份 keystore，丢失后无法更新已上架 App
```

### 4.2 配置签名

在 `app/build.gradle.kts` 增加（示例，口令建议放 `local.properties` 或环境变量，勿提交）：

```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file("../gba60hz-release.jks")
            storePassword = System.getenv("SIGN_STORE_PWD") ?: ""
            keyAlias = "gba60hz"
            keyPassword = System.getenv("SIGN_KEY_PWD") ?: ""
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
            isMinifyEnabled = false   // 如需开启，确保 proguard-rules.pro 保留桥接方法
            // ...
        }
    }
}
```

### 4.3 构建 Release

```bash
SIGN_STORE_PWD=xxx SIGN_KEY_PWD=xxx ./gradlew assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

或用 Android Studio 菜单 **Build → Generate Signed Bundle / APK**。

### 4.4 上架推荐用 AAB

```bash
./gradlew bundleRelease
# 产物：app/build/outputs/bundle/release/app-release.aab
```

Google Play 要求新应用用 AAB；国内应用市场多接受 APK。

## 5. 真机验证清单（构建后必做）

按此顺序逐项验证，发现问题对照文档二定位：

| # | 验证项 | 预期 |
|---|---|---|
| 1 | 冷启动 | 主页正常显示，无白屏/JS 报错 |
| 2 | 载入 demo（首页 ⋯ → 演示卡） | 进入游戏、60Hz 流畅、有画面 |
| 3 | 音频 | 有声音（首次可能需点一下屏幕解锁） |
| 4 | 导入 .gba 文件 | SAF 弹出、选中后进游戏；重启 App 游戏仍在（IndexedDB 持久化） |
| 5 | 存档/读档 | 存档菜单出现缩略图；读档恢复进度 |
| 6 | 触屏按键 | A/B/十字键/连发/震动正常 |
| 7 | 手柄（如有） | 蓝牙/USB 手柄即插即用，A/B/L/R/十字键映射正确 |
| 8 | 全屏/横屏 | 点全屏进入横屏，无遮挡；退出正常 |
| 9 | 返回键 | 设置页/菜单打开时返回键先关闭它们；再按退出 |
| 10 | 截图分享 | 截图保存到 DCIM/GBA60Hz，图库可见；分享可弹出系统面板 |

| 13 | 金手指/回溯 | 功能与网页版一致 |
| 14 | 外部打开 | 从文件管理器点 .gba 能唤起 App（视 ROM 匹配情况） |
| 15 | 长时间运行 | 连续游玩 30 分钟不崩、内存稳定 |

**抓取日志**：`adb logcat | grep -E 'GBA-JS|GBA60Hz'`，JS 错误会显示在 `GBA-JS` tag。

## 6. Play 商店上架要点

| 项目 | 说明 |
|---|---|
| **targetSdk** | 需满足上架当年要求（当前 35，2026 年可能需 36）；每年更新 |
| **隐私政策** | 应用不收集/共享数据；在 Play Console 数据安全和隐私声明中如实填写 |
| **权限声明** | 仅 VIBRATE / INTERNET，说明理由（震动反馈 / WebView 本地资源） |
| **ROM 版权** | App 本身不含商业 ROM；内置 demo 为 homebrew 测试卡。若上架，注意不要在素材里出现受版权保护的游戏画面 |
| **截图/描述** | 可展示 demo 画面；避免展示商业游戏 |
| **内容分级** | 模拟器工具类，通常定为所有人 |
| **AAB** | Google Play 需 AAB；国内商店用 APK |

## 7. 常见问题排查

| 现象 | 排查 |
|---|---|
| Gradle 同步失败 | 检查网络（需访问 google()/mavenCentral()）；Android Studio 内 File → Settings → Gradle 用本地发行版 |
| `WebViewAssetLoader` 类找不到 | 确认 `androidx.webkit:webkit` 依赖版本 ≥1.12 |
| 页面白屏 | 看 `adb logcat` 的 `GBA-JS` tag；多为 origin 或 asset 路径问题，确认 `APP_URL` 与 assets 文件名一致 |
| 存档不持久 | 确认用 https origin 加载而非 file://；检查 App 数据是否被清除 |
| 导入 ROM 无反应 | 确认 `onShowFileChooser` 被触发；SAF 返回 Uri 是否有效 |
| release 桥接失效 | 确认 proguard 规则保留 `@JavascriptInterface` 方法，或临时 `isMinifyEnabled=false` 验证 |
